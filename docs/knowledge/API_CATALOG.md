### 1.1. Interfaces de Vendorización y Validación UI/UX (`FWK-002`)

| Endpoint / Interfaz | Método / Tipo | Descripción | Contrato Entrada | Contrato Salida | Introducido en |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `scripts/sdd_vendor_update.py` | CLI (`uv run python ...`) | Verifica `VENDOR.lock.json` o instala/actualiza aisladamente `ui-ux-pro-max-cli@<X.Y.Z>` desde staging temporal con normalización LF. | `--verify [--pack-dir PATH] [--vendor-dir PATH]` \| `--version <X.Y.Z> [--apply] [--yes] [--pack-dir PATH]` | Código `0` (`[OK]` o `[DRY-RUN]` sin `--apply`); código `1` (`[ERROR]`/`[ABORTED]`) ante `VendorIntegrityError`, `ValueError` u `OSError` | `FWK-002` |
| `sdd_vendor_update.verify_vendor_lock(...)` | Python API (`scripts/sdd_vendor_update.py`) | Verifica esquema `VENDOR.lock.json`, rutas POSIX seguras, ausencia de symlinks/ficheros extra/faltantes y coincidencia exacta de `bytes` y `sha256`. | `vendor_dir: Path`, `lock_path: Path \| None = None` | `dict[str, Any]` (carga útil validada de `VENDOR.lock.json`) o lanza `VendorIntegrityError` | `FWK-002` |
| `sdd_vendor_update.update_vendor(...)` | Python API (`scripts/sdd_vendor_update.py`) | Ejecuta `npx --yes ui-ux-pro-max-cli@<version> init --ai antigravity --offline` (o `runner` inyectable) en `TemporaryDirectory`, valida `validate_data.py`, excluye 6 skills hermanas y `scripts/tests/`, calcula diff y aplica atómicamente si `apply=True`. | `version: str`, `pack_dir: Path`, `*, apply: bool = False`, `runner: Callable[[Sequence[str], Path], int] \| None = None` | `dict[str, Any]` (`version`, `applied`, `added`, `modified`, `removed`, `unchanged_count`, `file_count`, `pack_version_change`, y `lock` si `apply=True`); lanza `ValueError` o `VendorIntegrityError` | `FWK-002` |
| `sdd_vendor_update.compute_vendor_manifest_entries(...)` | Python API (`scripts/sdd_vendor_update.py`) | Recorre determinísticamente `vendor_dir` (omitiendo `VENDOR.lock.json`, `__pycache__` y `*.pyc`) calculando `sha256` y `bytes`. | `vendor_dir: Path` | `dict[str, dict[str, object]]` ordenado por ruta POSIX relativa; rechaza symlinks o escapes | `FWK-002` |
| `sdd_pack_registry` (extensiones `uiux` & `vendor_lock`) | Python API (`scripts/sdd_pack_registry.py`) | Extiende `parse_stack_config()` con validación estricta de `uiux`, `resolve_active_packs()` con coherencia `uiux.enabled` ↔ `capability-ui-design` tras Gate 00, `load_pack_manifest()` con `targets`/`upstream` y `resolve_pack_assets()` con `verify_vendor_lock()`. | Campos `uiux` en `sdd:stack-config` y `targets`/`upstream.vendor_lock` en `pack.json` | Lanza `StackConfigError` ante esquema/coherencia `uiux` inválida o `InvalidManifestError` si falla `verify_vendor_lock()` | `FWK-002` |
| `.agents/skills/ui-ux-pro-max/scripts/{search,validate_data}.py` | CLI Python stdlib offline (materializado) | Consulta offline de sistema de diseño (`--design-system --json`) y validación de datasets CSV/JSON (`12` dominios, `22` stacks). | `search.py "<query>" --design-system -p "<project>" --json` (y flags `--domain`, `--stack`, `--persist --output-dir <temp_dir>`); `validate_data.py` | JSON/Markdown/ASCII de sistema visual en stdout o código `0` (`OK: validated ...`) sin red ni `npx` | `FWK-002` |
